1.1 Команда uptime показывает, сколько времени сервер работает без перезагрузки, сколько пользователей подключено и среднюю нагрузку на систему за 1, 5 и 15 минут.
Команда free -h показывает использование оперативной памяти и swap.
Команда df -h показывает использование дисков и файловых систем. Если Use% близок к 90–100%, на сервере может быть проблема с нехваткой места.
Команда ss -tulpn показывает открытые сетевые порты и процессы, которые их используют. Ключ -t показывает TCP, -u показывает UDP, -l показывает слушающие порты, -p показывает процесс, -n показывает адреса и порты числами.

2.2 Команда journalctl -p err --since "1 hour ago" --no-pager показывает только ошибки из системного журнала за последний час. Ключ -p err выбирает сообщения уровня error и выше. Параметр --since "1 hour ago" ограничивает вывод последним часом.

<img width="1710" height="204" alt="image" src="https://github.com/user-attachments/assets/09670a54-b645-485a-9bae-244decfe3c78" />

Часть ошибок относится к графическому драйверу vmwgfx. В сообщениях указано, что драйвер vmwgfx запущен на неподдерживаемом гипервизоре. Это связано с виртуальной машиной и графической подсистемой. Так как используется Ubuntu Server и работа выполняется в терминале, эти ошибки не являются критичными для выполнения задания.

Также обнаружена ошибка PAM: система не смогла загрузить модуль pam_lastlog.so, потому что файл отсутствует. Этот модуль отвечает за информацию о последнем входе пользователя. Ошибка указывает на проблему в настройках PAM или отсутствие нужного модуля, но вход в систему продолжает работать.

Также присутствует сообщение Invalid DMI field header, которое связано с некорректной или неполной информацией об оборудовании в виртуальной среде. Для работы сервера это обычно не критично.

Команды start и stop управляют текущим состоянием сервиса. Команда start запускает сервис сейчас, а команда stop останавливает сервис сейчас.
Команды enable и disable управляют автозагрузкой. Enable включает автоматический запуск сервиса при старте системы, а disable отключает автоматический запуск. Эти команды не означают немедленный запуск или остановку сервиса.
Команда sudo nginx -t проверяет конфигурационные файлы NGINX без перезапуска сервиса. Если вывод содержит syntax is ok и test is successful, значит конфигурация корректная.
Команда sudo systemctl restart nginx выполняет полный перезапуск сервиса NGINX. Она полезна после изменения конфигурации, когда нужно применить новые настройки.

Команда pidof cron показала PID процесса. Далее команда ps -o pid,ppid,cmd -p 792 показала, что родительский PID процесса cron равен 1, а команда запуска - /usr/sbin/cron -f -P. Это означает, что родительским процессом является systemd, главный процесс системы. Команда pgrep -P 792 -a не вывела результатов, значит на момент проверки у процесса cron не было дочерних процессов. Команда pstree -p 792 показала дерево процесса в виде cron(792), что также подтверждает отсутствие дочерних процессов.

Для безопасной проверки завершения процесса был создан тестовый процесс командой sleep 300 &. Символ & запустил процесс в фоновом режиме. Процесс получил PID 1319, что было проверено командой pidof sleep. Затем тестовый процесс был завершён командой kill 1319. После проверки командой ps -p 1319 активный процесс уже не отображался, а сообщение Terminated sleep 300 подтвердило, что процесс был  завершён.
